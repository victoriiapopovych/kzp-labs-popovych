# Звіт до лабораторної роботи №1

## 1. Тема, номер роботи та варіант

Лабораторна робота №1.

Тема: «Розгортання Java-проєкту та базова обробка даних».

Предметна область: метеостанція.

Варіант: 18.

Операційна система: Windows.

## 2. Мета роботи

Мета роботи — створити базову версію консольної Java-програми та підготувати структуру репозиторію для її подальшого розвитку.

На першому рівні реалізовано читання текстових даних, перевірку коректності записів, базові числові обчислення, форматований вивід результатів у консоль і текстовий файл.

Для варіанта 18 «Метеостанція» програма обробляє погодні спостереження та визначає кількість коректних записів, мінімальну температуру, середню вологість і найбільшу швидкість вітру.

## 3. Постановка задачі

Потрібно розробити консольну Java-програму для обробки даних метеостанції.

Один запис має формат:

`date;temperature;humidity;pressure;wind`

Поля запису:
- `date` — дата спостереження, `String`;
- `temperature` — температура, `double`;
- `humidity` — вологість, `double`;
- `pressure` — атмосферний тиск, `double`;
- `wind` — швидкість вітру, `double`.

Програма повинна:
1. прочитати записи з UTF-8 файла;
2. перевірити кожний рядок;
3. повідомити номер і причину пропуску некоректного рядка;
4. не враховувати хибні записи під час обчислень;
5. визначити кількість коректних записів;
6. знайти мінімальну температуру;
7. обчислити середню вологість;
8. знайти найбільшу швидкість вітру;
9. сформувати один звіт;
10. вивести звіт у консоль і записати його у файл.

## 4. Структура програми

Після налаштування другого рівня проєкт має таку основну структуру:

```text
kzp-labs-popovych/
├── .mvn/
│   └── wrapper/
│       └── maven-wrapper.properties
├── data/
│   └── input.csv
├── src/
│   ├── main/
│   │   └── java/
│   │       └── ua/
│   │           └── lpnu/
│   │               └── kzp/
│   │                   └── Main.java
│   └── test/
│       └── java/
├── .editorconfig
├── .gitattributes
├── .gitignore
├── mvnw
├── mvnw.cmd
├── pom.xml
├── README.md
└── REPORT.md
```

Файл `pom.xml` описує Maven-проєкт, його залежності та плагіни.

Файли `mvnw`, `mvnw.cmd` та каталог `.mvn/wrapper/` утворюють Maven Wrapper і забезпечують використання зафіксованої версії Maven.

Каталоги `target/` та `out/` не входять до репозиторію, оскільки містять результати, які можна автоматично відтворити під час збірки або запуску програми.

## 5. Інфраструктура проєкту

На першому рівні було створено базову структуру Java-проєкту та Git-репозиторій.

У проєкті використовуються службові файли:
- `.editorconfig` — для однакового форматування файлів;
- `.gitattributes` — для нормалізації текстових файлів між різними операційними системами;
- `.gitignore` — для виключення з Git згенерованих файлів і каталогів.

Вхідні та вихідні текстові файли обробляються у кодуванні UTF-8.

Для роботи зі шляхами використовується `Path`.

На другому рівні проєкт переведено на Maven. Додано файл `pom.xml` з такими основними налаштуваннями:
- `groupId` — `ua.lpnu.kzp`;
- `artifactId` — `lab01`;
- версія — `1.0.0`;
- версія Java — 21;
- кодування — UTF-8;
- JUnit Jupiter 5.12.2 як тестова залежність;
- SpotBugs для статичного аналізу;
- Maven Shade Plugin для створення виконуваного JAR.

Додано Maven Wrapper версії 3.3.4, який використовує Maven 3.9.11.

На Windows Maven-збірка запускається через `mvnw.cmd`.

Перевірка Maven-проєкту:

```powershell
.\mvnw.cmd test
```

Команда виконана успішно та завершилася повідомленням `BUILD SUCCESS`.

Статичний аналіз виконується командою:

```powershell
.\mvnw.cmd verify
```

Під час фази `verify` запускається SpotBugs. Перевірка завершилася успішно.

Створення виконуваного JAR:

```powershell
.\mvnw.cmd package
```

Після успішної збірки створюється файл:

```text
target/lab01-1.0.0.jar
```

JAR успішно перевірено командами:

```powershell
java -jar target/lab01-1.0.0.jar --help
```

та

```powershell
java -jar target/lab01-1.0.0.jar
```

Програма з JAR зберігає ту саму поведінку, що й під час звичайного запуску Java-класу.

Каталог `target/` не додається до Git, оскільки він автоматично створюється Maven під час збірки.
